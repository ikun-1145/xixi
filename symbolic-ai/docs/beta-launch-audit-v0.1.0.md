# Sunland AI v0.1.0 Beta Launch Audit

## 结论

**状态：有条件通过，可进行有主持人的小规模封闭测试，不建议直接公开放量。**

当前 Web/Flutter 的核心对话、身份隔离、错误降级、Knowledge/Memory、Provider
锁定和本地 Diagnostics 已有自动化保护。此次准备工作未修改产品行为；以下未完成项
需要通过测试主持人流程或后续单独批准的产品改动处理。

真实用户进入前有一个外部 Launch Gate：必须复核云端 `conversations` 等用户数据的
服务端隔离策略。项目长期说明记录了部分 Supabase 表未启用 RLS，而相关后端不完整地
包含在本仓库内，因此本次只能确认客户端命名空间隔离，不能证明数据库侧的访问控制。
在此项关闭前，只应使用受控测试账号和非敏感测试内容。

## 审计范围与方法

- 阅读 Web 登录、首次会话创建、模型选择、错误处理、设置、Knowledge/Memory 和
  Beta Diagnostics 实现与既有测试。
- 阅读 Flutter 登录、空会话、快捷入口、模型选择和错误反馈实现。
- 在本地浏览器实际检查未登录首次进入、空邮箱、错误邮箱、设置空状态，以及展开后的
  Diagnostics 可访问文本。
- 运行发布 Bundle 的 Knowledge/Memory 产品场景，不导入 Core 内部模块。
- 对比 v0.1.0 SDK API Surface、Bundle hash 和 Web/Flutter 宿主回归。

审计未访问真实账号、浏览器存储、生产数据库或用户数据，也未发起真实验证码和付费操作。

## 1. 用户首次体验

| 检查项 | Web | Flutter | 结论 |
|---|---|---|---|
| 未登录入口 | 邮箱验证码、无需注册、协议与隐私入口清楚 | 有产品说明、邮箱登录和协议入口 | 通过 |
| 输入校验 | 空邮箱与格式错误就地反馈 | 现有登录状态和错误反馈 | 通过 |
| 首个会话 | 身份验证后自动创建一个空会话 | 无消息时展示欢迎页 | 通过 |
| 可开始操作 | 输入框与模型菜单可用 | 提供兽聚、灵感、聊天快捷入口 | 通过 |
| Sunland 发现 | 位于模型菜单，只有名称，没有能力说明或示例 | 明确写明“本地符号推理，不使用 DeepSeek” | 部分通过 |
| Knowledge/Memory 入门 | 首屏无主动示例，主要依赖首次回复引导 | 快捷入口未覆盖教学或姓名记忆 | 部分通过 |

产品风险：没有主持人说明时，Web 新用户可能把页面标题“Sunland AI”与默认选中的
DeepSeek 模型混为一谈，也不容易主动发现“教学知识”和“记住姓名”的区别。

## 2. 错误提示与空状态

### 已满足

- 登录页覆盖空邮箱、邮箱格式、验证码格式、网络不可达、超时、限频和服务端错误。
- 身份失效统一提示重新登录，不使用本地缓存身份继续运行。
- Sunland、DeepSeek 与 Flutter 请求失败均给出重试、检查网络或稍后再试的下一步。
- Knowledge 列表区分正在读取、无教学知识、读取失败和需要重新登录。
- Diagnostics 区分默认关闭、无本地数据、保留数据、清除成功和身份失效。
- 危险删除操作说明不可恢复，以及不会影响聊天记录或内置知识的边界。

### 待改进

- Web 登录仍有部分错误通过浏览器 `alert` 显示，并可能附带服务端原始详情；适合内部
  Beta 排障，但不够统一。
- 设置页未登录状态仍展示升级入口和完整数据区，虽然操作会被阻止，但可能造成理解负担。
- 设置页页脚显示 `v1.1`，没有说明它是客户端版本还是 Core `v0.1.0`，容易造成版本混淆。
- Flutter 当前 `flutter analyze` 报告 75 项既有 lint（0 error、4 warning、71 info），
  主要涉及弃用 API、异步 `BuildContext`、未使用私有方法和生产日志。自动化测试通过，
  但公开发布前应建立并逐步收紧静态分析基线。

上述均不是封闭 Beta 的阻断项，但应在公开发布前处理。

## 3. Knowledge / Memory 引导

### 已满足

- Core 在不知道答案时邀请用户补充知识；教学成功后明确说明已记录并可再次询问。
- “我叫什么”在没有记录时会主动邀请用户提供名字；提供后可跨 Engine 恢复。
- 设置页将“姓名记忆”和“用户教学知识”分成两个独立区域。
- 清除姓名不会影响聊天记录；清除教学知识不会影响内置知识、Memory 或其他账户。
- Web/Flutter 均通过同一 Core Bundle 使用相同 Knowledge/Memory 行为。

### 待改进

- Web 和 Flutter 首屏都没有直接给出“我叫小蓝”“猫属于动物”“猫会什么”一类
  可点击示例。
- 当前引导是响应式而非主动式，需要 Beta 主持人在首次任务中提供明确测试语句。

本次不增加引导卡片或快捷操作，以避免改变 Web/Flutter 行为和新增 AI 能力。

## 4. Beta Diagnostics 用户理解

### 已满足

- 默认关闭，并收起在设置页“隐私与诊断”区域。
- 明确说明仅保存在当前设备、不会自动上传，以及不包含聊天内容、姓名、教学知识或账号标识。
- 开启需要确认，可随时关闭；关闭后明确说明已有快照仍保留。
- 支持查看、复制、导出匿名 JSON 和独立清除。
- 只统计开启后的 Sunland 请求，不作用于 DeepSeek。

### 待改进

- `Context 使用`、`Legacy 回退`、`副作用阻止`、`安全降级` 和“性能分桶”属于内部术语，
  普通 Beta 用户难以理解。
- Diagnostics 不自动上传是正确的隐私边界，但当前没有在 UI 内说明用户应通过何种渠道
  把导出文件交给测试主持人。
- Flutter 当前没有同等 Diagnostics 管理入口；测试计划不得暗示两端都能采集。

封闭 Beta 中应由主持人解释：这些计数是本机聚合排障数据，不是用户评分，也不会自动
发送；只有用户主动导出后才可提交。

## 5. 风险分级

### P0 — 真实用户测试前必须关闭

1. **服务端用户数据隔离复核**：确认生产 `conversations` 及相关表的数据库策略或受信
   网关确实阻止跨用户读写。客户端命名空间测试不能替代服务端授权。

### P1 — 封闭 Beta 可由主持流程缓解

1. Web 首屏未解释当前模型与 Sunland 的差异，也没有 Knowledge/Memory 示例。
2. Diagnostics 指标包含内部术语。
3. 需要建立明确的反馈接收渠道、响应负责人和用户主动导出 Diagnostics 的说明。

### P2 — 公开 Beta 前处理

1. 统一 Web 登录错误展示，减少原始技术详情。
2. 澄清设置页 `v1.1` 与 Core `v0.1.0` 的版本含义。
3. 评估未登录设置页是否应隐藏不可用的升级和数据操作。
4. 清理或显式基线化 Flutter 的 75 项静态分析问题，优先处理异步生命周期与 4 项 warning。

## 6. 建议测试范围

- 5–15 名受控测试者，使用专门测试账号和非敏感内容。
- Web 与 Flutter 各至少覆盖 3 名测试者，并安排同账号跨端恢复。
- 每位测试者完成登录、选择 Sunland、身份/教学/追问、错误恢复、Knowledge 清除边界和
  Diagnostics 理解访谈。
- 任何身份串号、跨用户数据可见、删除影响其他用户、SDK Surface/hash 漂移均立即停止测试。

逐项执行步骤见 [`beta-test-checklist.md`](./beta-test-checklist.md)。
