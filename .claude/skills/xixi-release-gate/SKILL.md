# 霜蓝发布门禁

只根据可复现证据给出发布结论，不把未执行的检查描述成已通过。

## 建立审查范围

1. 读取 `git status --short`、`git diff --stat` 和完整相关 diff，区分本次改动与用户已有改动。
2. 把文件映射到公开页面、AI 子应用、认证、数据、支付、Worker、Edge Function、PWA 或 Codex 配置。
3. 对高风险区域同时应用 `$xixi-auth-data-safety`；对前端行为同时应用 `$xixi-frontend-workflow`。

## 执行门禁

- 总是运行 `git diff --check`。
- 修改根项目 HTML、CSS、JavaScript 或测试时运行 `npm test`。
- 修改 `.agents/skills/*` 时对每个 Skill 运行 `quick_validate.py`，并确认没有 TODO 占位内容。
- 修改 `.codex/*.toml` 时解析 TOML，并用当前 Codex CLI 的只读命令确认配置可加载。
- 涉及 UI 时检查关键视口和交互路径；涉及网络时检查错误、超时、重试与取消路径。
- 检查 secrets、XSS、开放重定向、权限扩大、API 格式变化、竞态和重复提交。
- 不执行生产部署、数据库写入、真实支付或破坏性命令，除非用户明确要求并授权。

## 报告结论

按以下顺序输出：

1. 阻断发布的问题，包含文件和可复现证据；
2. 已通过的自动化与手工检查；
3. 未执行或无法执行的验证及原因；
4. 最终结论：`可发布`、`有条件可发布` 或 `不可发布`。

如果没有发现问题，明确说明“未发现阻断项”，不要声称绝对安全或无回归。
