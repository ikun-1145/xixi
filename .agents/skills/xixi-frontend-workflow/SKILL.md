# 霜蓝前端工作流

遵循现有无框架架构，保留页面可直接部署的特性。

## 定位真实所有者

1. 先读取页面入口和它加载的脚本、样式，再定位实际事件处理器或状态所有者。
2. 搜索相似组件、工具函数和测试，优先复用 `p/css/tokens.css`、`p/css/base.css`、公共脚本与现有 DOM 模式。
3. 追踪事件顺序、异步状态、请求锁和重复触发；移动端交互同时考虑 pointer、touch 与合成 click。
4. 若触及登录、token、API、Supabase、支付或路由，立即同时应用 `$xixi-auth-data-safety`。

## 实施最小改动

- 保持原生 HTML/CSS/JavaScript 风格，不引入框架或状态库。
- 只修改拥有该行为的最小文件集合，不顺带重构大文件。
- 保持请求与响应格式、路由、localStorage key、跨端消息字段兼容。
- 使用安全 DOM API；对外部或用户内容避免 `innerHTML`，必要时复用现有净化与 Markdown 渲染链。
- 使用设计 token 和现有响应式断点，防止溢出、布局跳动和触控区域过小。
- 新增或修改用户可见系统文案时，同步简中、繁中、英、日、韩、西六种语言；不要翻译用户内容或外部活动数据。
- 保持桌面键鼠、移动 Safari / Chrome 和 PWA 场景的既有行为。

## 验证改动

1. 为修复补充或更新最接近真实回归路径的测试，避免只断言实现文本。
2. 运行相关单测；影响公共 JS、HTML 或 CSS 时运行 `npm test`。
3. 运行 `git diff --check` 并自审事件重复、竞态、XSS、空状态和错误状态。
4. 对触摸、布局、PWA 或浏览器时序问题进行真实浏览器验证；不能验证时明确列出设备测试缺口。

不要把静态正则测试通过描述成真实移动端体验已验证。
