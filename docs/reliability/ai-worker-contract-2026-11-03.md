## 2. 生产 HTTP 错误契约（现网代码观察）

| 服务端场景 | HTTP | 响应结构/示例 | 前端处理原则 |
|---|---:|---|---|
| 当日免费配额耗尽 | 429 | `{ "error": "LIMIT", "remain": 0, "isPro": false }` | 仅此场景显示每日配额耗尽弹窗 |
| 应用级 KV 频率限制 | 429 | `{ "error": "Too Many Requests" }` | 普通限流提示，不弹每日耗尽弹窗 |
| 模型上游返回 429 | 429 | 服务繁忙的通用中文错误信息 | 普通限流提示，不弹每日耗尽弹窗 |
| 重复提交/进行中/冲突 | 409 | `REQUEST_COMMITTED` / `REQUEST_IN_FLIGHT` / `REQUEST_CONFLICT` | 提醒检查会话状态，避免重复发送 |
| 配额服务忙或不可用 | 503 | `QUOTA_BUSY` / `QUOTA_UNAVAILABLE` | 服务暂不可用，不视为额度耗尽 |
| 模型处理结果未知 | 503 | `MODEL_OUTCOME_UNKNOWN` | 结果不确定，不建议盲目重试 |
| 配额释放结果未知 | 503 | `QUOTA_RELEASE_UNKNOWN` | 结果不确定，不建议盲目重试 |
| 上游模型 HTTP 402 | 503 | 服务暂不可用的通用错误 | 前端**无法判断确切上游状态**；不宣称余额不足 |
| 上游其他错误 | 通常 502 | 通用 AI 服务异常 | 统一安全提示，不回显上游正文 |
| 非 Pro 请求 Pro 模型 | 403 | `PRO_REQUIRED` | 提示检查会员资格 |

备注：

1. 上表是生产版本 147 的**观察结果**，不是新协议提案。
2. `ai_quota_reserve`、`ai_quota_finish` 等 RPC 的完整并发语义还需要与数据库定义、测试环境共同复核。
3. 后端某些异常分支包含 `finally` 返回处理，后端维护时必须覆盖返回值优先级和配额释放状态，不可直接以“交换状态码”代替系统性修复。
4. 不能把单个 HTTP 503 直接诊断为余额不足、CPU 超限或 Supabase 故障。必须依靠可审计的服务端阶段性错误类别和请求关联信息。
5. 不应将 DeepSeek 原始错误响应、密钥、邮箱、JWT、用户聊天内容直接写入日志或客户端提示。

## 3. 源码恢复和“可重复构建”门禁

在能够维护线上 `ai` Worker 之前：

1. **定位原始工程**：查找提交 `55661fb175038577cf598aaa4ac3a58e4100a79a` 所属仓库/工作区及锁文件、Wrangler 配置、打包脚本。
2. **核对代码**：只读比较原始代码与线上版本 147 业务契约；重点是验证码、登录刷新、自建 JWT、配额 RPC、DeepSeek 流、定时任务和 CORS。
3. **构建复现**：在隔离环境重建 bundle，比较输出与发布备注记录的 SHA-256。无法复现时标记 `UNVERIFIED_ARTIFACT`；不得用“看着类似”判定可安全覆盖。
4. **测试优先**：使用不含真实凭据的 Mock 覆盖 429 LIMIT/限流、409、402→503、502、503 未知结果、SSE 中断、配额提交/释放、验证码并发。
5. **非生产预览**：确认独立预览环境、隔离绑定、无生产写权限、无真实邮件/支付副作用；不得直接指向生产 Supabase service-role。
6. **发布审批**：明确改动文件、兼容影响、观察指标、失败阈值、上线审批人和回滚操作后，再获单独授权执行。
7. **上线后验证**：区分上游失败率、Worker 5xx、CPU、Cron 业务成功心跳、错误日志采样和用户端投诉；与上线前基线对照。

严禁将 Cloudflare 在线读取的打包脚本（可能包含敏感常量或构建信息）直接复制进公开仓库，并声明它已经是可重复构建的源代码。

## 4. 回滚说明

Cloudflare 官方说明：Worker 回滚会**立即创建新的部署**并使指定旧版本接管服务；关联的资源绑定本身不会自动恢复。回滚前必须确认 KV/D1/R2 等绑定存在，数据库结构与旧代码兼容。

- 当前已知基准：版本 **147**，其生产实测功能是当前上线前比较基线。
- 版本 **146** 仅为历史版本，**不得未经复核自动回退至 146**，尤其在期间有 JWT、KV、配额 RPC 或认证逻辑变更时。
- 任何回滚都是生产写操作，需要项目负责人单独授权。
- 官方说明：https://developers.cloudflare.com/workers/versions-and-deployments/rollbacks/
