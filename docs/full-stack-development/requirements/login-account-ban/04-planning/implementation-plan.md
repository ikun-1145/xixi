# 实施计划

开发流：`strict-fullstack`，因为改动触及认证与用户数据，但不包含 schema/API 变更或新视觉设计。

1. 为短期数据库 Token 客户端增加一次性、无持久化交换能力，并补跨用户、过期与缓存回归测试。
2. 新增独立封禁状态读取器，只读当前 RLS 用户行，规范化管理员原因，所有不可读状态保守失败。
3. 在 `login.html` 的 Token 持久化前接入检查，封禁时清理缓存并复用现有弹窗。
4. 补齐六语言文案和真实调用顺序测试。
5. 完成聚焦测试、全量测试、浏览器视口检查、安全审查、完整 diff 与发布门禁。

当前会话未安装 Superpowers 执行工具，也未提供 full-stack-development 生命周期 MCP；以测试先行、主代理自审、发布门禁和最终验收报告提供等价的本地证据，不创建分支、不提交、不部署。
